# 빌드·배포 검증 체크리스트

## 1. 게임 동작 (브라우저에서 index.html 열기)
- [ ] 5화면 흐름(첫→설명→문제→보상→결과) 1판(10문제) 완주
- [ ] 문제 은행이 전부 해당 차시 유형인지 표본 점검
- [ ] 각 단계 보기에 정답 + 대표 오답 등장
- [ ] 앞 단계와 화면 정보만으로 최종 답이 이미 하나로 정해지면 마지막에 같은 값을 다시 고르게 하지 않고 자동 완성 연출로 보여 줌
- [ ] 각 단계 정답 직후 계산판·칸·블록이 정답값으로 바뀌고 짧은 확인 문구가 보임(선택지 색만 바뀌면 실패)
- [ ] 마지막 단계 뒤 보상 모달이 뜨기 전에 완성식이나 완성값이 먼저 보이고, 모달이 정답 확인을 가리지 않음
- [ ] 마지막 단계 보상 버튼은 완성된 수학 관계를 충분히 본 뒤 아직 알 수 없는 랜덤 보상을 여는 실제 이유가 있음(예: `바람 보기`, `상자 열기`)
- [ ] 문제 풀이·확인·마지막 버튼마다 `누르기 전 모르는 것 → 필요한 수학적 판단 → 누른 뒤 보이는 증거`가 이어지며, 하나라도 비는 버튼은 제거됨
- [ ] 랜덤 보상(증가/감소/0/즉시완성/특별) 모두 발생 가능
- [ ] 중간 오답 시 "결함/누수" 처리(일부러 틀리기 차단)
- [ ] 결과 = 차시 자체 완결형 등급 + 정답 수 게이트, 등급 이미지 표시

## 2. 교과서식 학습 UI와 전환 상태

- [ ] 문제 화면마다 `1순위 학습 대상 / 2순위 보조 정보 / 3순위 상태·장식`을 선언함
- [ ] `영역/우선순위/정보 묶음 수/width/height/Stage 폭 비율/Stage 면적 비율/판정` 표를 실제 브라우저 rect로 기록함
- [ ] 1순위 학습 대상이 콘텐츠 레이어에서 가장 큰 단일 영역이며 글자 크기·대비도 가장 강함
- [ ] 서로 연결된 식·표현이 둘 이상 들어간 핵심 패널의 실제 폭이 Stage 폭의 `65%` 이상임. 미만이면 재설계하고 예외 이유와 대안 캡처를 남김
- [ ] 문제 대기·정답 확인·마지막 완료에서 핵심 계산판이 다른 열로 이동하거나 좁아지지 않으며, 완료식·다음 행동 상자와 작업 영역 좌우 경계·중심 차이가 `1px` 이하임
- [ ] 장식 배경·캐릭터·보조 카드가 핵심 계산판·조작판·선택지를 좁은 열로 밀어내지 않음
- [ ] 정보량이 많은 패널에서 글자·줄간격·터치 영역을 먼저 줄이지 않고 패널 확대, 중첩 테두리 제거, 장식 축소를 먼저 적용함
- [ ] 3초 보기와 흐림/눈가늘임 상태에서도 1순위 학습 대상이 가장 먼저 보임
- [ ] 문제 은행 전체의 수학적 판단 횟수와 물리 입력 횟수를 따로 셈
- [ ] 정답 경로의 최소·중앙값·평균·최대 탭·드래그·키 입력 수와 대표 문제를 기록함
- [ ] 같은 판단 뒤 동일한 물건 놓기·누르기가 세 번 이상이면 매번 새 판단이 필요한 이유를 기록하고, 이유가 없으면 조작을 줄임
- [ ] `버튼/상태 | 누르기 전 모르는 것 | 필요한 수학적 판단 | 누른 뒤 보이는 증거 | 배움에 보태는 점 | 유지/제거` 표를 `PLAN.md` 또는 `BENCHMARK_AUDIT.md`에 기록함
- [ ] 검산처럼 결과가 정의상 처음 수와 같고 처음 수가 이미 보이는 문제에서 처음 수를 다시 선택·입력하는 중복 단계가 없음
- [ ] 결정된 결과는 자동 연출로 보여 주고, 학생 입력은 결과가 정해지기 전의 수·위치·관계 판단 또는 그럴듯한 오답의 비교·수정에 사용함
- [ ] 학생이 답을 먼저 확정한 뒤 반복 배치가 확인 애니메이션으로 실행되며, 시스템이 학생 답 없이 정답을 자동 생성하지 않음
- [ ] 설명 화면이 조작법뿐 아니라 각 단계가 최종 답의 어느 부분을 만드는지 보여 줌
- [ ] 계산 순서와 공간 배치를 실제 교과서 풀이와 대조함
- [ ] 세로 계산의 자리 열, 나눗셈의 몫·곱한 값·빼는 선·남은 수·내려오는 수의 열이 맞음
- [ ] 계산판 자리 숫자와 선택지·지시문·확인 문구의 실제 값을 구별함(예: 칸 `1`, 학생 말 `몫 10`)
- [ ] 문제 은행 전체에서 `7십`, `2십` 같은 숫자+`십` 표기와 어색한 조사를 검사함
- [ ] 문제 화면 왼쪽 위에 `에듀잇티 수학 게임`, 같은 상단 줄에 단원 배지가 보임
- [ ] 큰 문제의 숫자와 `÷`·`×`·`−`, 나눗셈 괄호선, 몫 칸 사이 간격과 기준선이 자연스러움
- [ ] 숫자 슬롯에 tabular 숫자 또는 고정 폭을 써서 값이 바뀌어도 정렬이 흔들리지 않음
- [ ] 너무 작은 답과 너무 큰 답을 각각 재현해 오답 이유가 현재 계산판·물건으로 보임
- [ ] 각 단계 정답 확인을 따로 재현하고, 학생이 고른 값이 계산판·칸·물건에 들어감
- [ ] 지시문과 피드백이 동시에 겹치지 않고 `?` 칸·숫자·화살표·선택지를 가리지 않음
- [ ] 정답 확인이 학생이 읽을 수 있는 시간 동안 유지되고 다음 단계가 즉시 덮지 않음
- [ ] 마지막 완성값을 학생이 확인한 뒤 보상을 열며, 모달이 먼저 덮지 않음
- [ ] `1280×800`, `1024×768`, 사용자가 문제를 발견한 창과 비슷한 크기에서 같은 상태를 확인함
- [ ] 사용자가 겹침·넘침·핵심 영역 과소 크기 같은 시각 위계 실패를 발견한 실제 `innerWidth×innerHeight`, DPR, Stage rect를 기록하고 그 정확한 viewport를 `lesson.json > qa.viewports`에 이름 있는 회귀 항목으로 추가함
- [ ] 실패 viewport는 한 번만 쓰는 수동 확인이 아니라 전용 QA가 매번 도는 영구 회귀 테스트이며, 사용자가 지원 범위를 바꾸기 전까지 삭제하지 않음
- [ ] 계산판/SVG 바깥 표면, 문제 카드, 지시문, 피드백, 선택지·숫자판의 실제 rect를 재고 형제 영역 교차가 0px이며 눈에 보이는 간격이 있음
- [ ] SVG는 요소 전체 rect만 보지 않고 배경 도형 rect와 모든 `<text>`의 `getBBox()`/렌더 rect가 의도한 계산판 안에 드는지 검사함
- [ ] 문제 대기, 대표 오답 양방향, 각 단계 정답 확인, 다음 단계 대기, 마지막 확인에서 같은 표면 경계 검사를 반복함
- [ ] z-index나 덮는 패널로 겹친 부분을 숨기지 않고 grid/flex track, contain, overflow 경계로 구조적으로 분리함
- [ ] 실제 렌더에서 문제 숫자 `32px`, 계산판·선택지 핵심 숫자 `20px`, 지시문 `14px`, 터치 영역 `42×42px` 이상의 기본 바닥값을 확인함(차시 계약이 더 크면 더 큰 값 우선)
- [ ] 현재 학생 UI 변경 뒤에 만든 캡처만 증거로 쓰고, 오래된 캡처는 `_archive/`로 구분함
- [ ] 상태별 캡처 파일과 화면 크기, 남은 P0/P1을 `REPORT.md`에 기록함

### 기준 차시 비교

- [ ] 새 차시·학습 조작 변경·대형 화면 변경이면 기본 비교군인 3학년 2학기 1단원 1~4차시와 비교함
- [ ] 1차시의 보상 손익·오답 손해, 2차시의 계산 구조·진행감, 3차시의 현재 위치·다음 목표, 4차시의 단계 확인·검증 완결성을 강점별로 봄
- [ ] 한 차시의 겉모양을 통째로 복제하지 않고, 현재 차시 테마에 필요한 기능만 옮김
- [ ] 비교 항목을 `필수 계약`, `기준 차시 대비`, `제품 선택`으로 나누고, 기준 차시보다 나아진 직접 조작·오답 피드백은 `기준 이상`으로 기록해 보존함
- [ ] 수학적 판단, 한 화면 한 행동, 그럴듯한 오답, 오답 이유, 정답값 반영, 마지막 완성값 확인을 모두 통과함
- [ ] 설명 그림의 물건 수·묶음 수·식이 실제 수학 관계와 정확히 맞음
- [ ] 랜덤 보상, 빈손 금지, 얻기 어려운 최고 결과, `다음엔 더 멀리`가 함께 있음
- [ ] 학습 조작을 바꿨다면 모델·화면·설명·학생 문구·테스트·문서·스크린샷을 같은 변경 묶음으로 갱신함
- [ ] 자동 검사와 실제 화면 눈검사를 따로 기록하고, 오답 양방향·각 단계 정답·마지막 확인을 결정적으로 재현함
- [ ] 캡처 전에 모든 실행 이미지의 `complete && naturalWidth > 0`과 가능하면 `img.decode()` 완료를 확인하고, 글자·아이콘·버튼 면·캐릭터가 한 화면 크기에서만 비면 증거 세트를 다시 만듦
- [ ] 생성 원본 PNG나 파일 치수만 보지 않고 실제 `index.html`이 참조하는 WebP의 시각 내용을 확인함
- [ ] REPORT.md의 현재 PASS는 이번 코드에서 종료 코드 0을 다시 확인한 명령뿐이며, 전용 QA 실패를 공통 검사 PASS로 상쇄하지 않음
- [ ] `index.html`과 차시 설정의 이미지·스크립트 참조를 `git ls-files`와 대조하고, 차시 폴더와 `_lessons/` 원본에서 추적 밖 런타임 자산이 0개임을 확인함
- [ ] 현재 흐름과 맞지 않는 전용 QA·문서·스크린샷은 삭제하지 않고 `_archive/`에 날짜나 버전을 남겨 분리함
- [ ] 차시 폴더의 `BENCHMARK_AUDIT.md`에 `검사 항목/분류/기준 증거/대상 증거/판정/우선순위/다음 행동`을 적고, 공통 매트릭스 뒤 차시별 상세 체크를 둠
- [ ] 백엔드나 화면 복잡도를 늘리는 선택 항목은 임의로 넣지 않고 사용자에게 결정받음

## 3. 효과 설계 (references/effect-design.md 대조)
- [ ] 단계 정답 효과가 방금 고른 칸/블록/부품에만 짧게 붙음
- [ ] 문제 완료 후 계산 결과가 중심 보상 오브젝트로 이동하는 연출이 있음
- [ ] 중심 보상 오브젝트가 차오름/쌓임/켜짐/열림/붙음처럼 물질감 있게 변함
- [ ] 랜덤 이벤트(증가/대량/감소/0/즉시완성/특별)가 글 없이도 다르게 느껴짐
- [ ] 결과 전 측정/스캔 연출로 최종 등급 공개 전 기대감이 생김
- [ ] 효과가 문제·현재 단계·한 줄 지시·선택지를 가리지 않음
- [ ] 보상 팝업이 뜰 때 정적이지 않고 등장 모션(CSS transition 또는 `requestAnimationFrame`)이 한 번 이상 작동
- [ ] 보상/피드백 모달은 버튼을 제외하고 보이는 텍스트가 큰 결과 라벨 또는 변화량 1개로 줄어 있음
- [ ] 모달 안에 긴 설명 문장이 기본 노출되지 않고, 제목·본문·버튼이 같은 뜻을 반복하지 않음
- [ ] `출하!` + `출하 보기`, `결과` + `결과 보기` 같은 반복 문구가 없음
- [ ] `prefers-reduced-motion: reduce`에서 큰 이동·흔들림이 줄어듦

## 4. 화면 계약 (SERIES_CONTRACT.md 대조)
- [ ] 첫 화면 3요소(제목·한 줄 목표·시작 버튼) 최우선
- [ ] 새 표준 커버는 `<main class="game" data-cover-standard="generated-title-overlay">`를 선언함
- [ ] 새 차시와 생성형 시작 버튼 이관 완료 커버는 `data-cover-start-standard="generated-button-art"`를 선언함
- [ ] 첫 화면 배경은 글자 없는 `cover-generated.webp`를 `<img class="raster-bg">`로 깔고 `object-fit: cover`를 사용함
- [ ] 첫 화면에 매스몬이 보인다면 별도 `<img class="cover-mathmon">` 오버레이가 아니라 `cover-generated.webp` 생성 장면 안에 함께 들어 있음
- [ ] 첫 화면 제목이 단순 큰 HTML 글자처럼 보이지 않고, 배경과 어울리는 타이포그래픽 포스터/워드마크 또는 래스터 타이틀 아트로 보임
- [ ] 제목을 그림 자산으로 쓰는 경우 기존 커버 배경은 유지되고, 보이는 제목만 `<img class="hero-title-art">` 독립 오버레이로 얹혀 있음
- [ ] 제목 오버레이는 실제 `image_gen`/GPT Image 생성 산출물이며, 로컬 폰트/Pillow/canvas/SVG/CSS로 만든 텍스트 이미지가 아님
- [ ] 제목 자산은 생성 원본(`title-*-source.png` 또는 `title-*-chromakey.png`), 투명 PNG(`title-*-generated.png`), 배포 WebP(`title-*-generated.webp`)가 함께 있음
- [ ] 제목 오버레이는 GPT Image 등으로 만든 래스터 자산이며, 실제 제목은 `visually-hidden` 텍스트로 남아 있고 한글 철자가 캡처에서 정확함
