# 매스몬 별 줍기 기준 차시 비교 감사

점검일: 2026-07-14
대상: `3-2-2-3-mathmon-star-pickup`
비교군: 3학년 2학기 1단원 1~4차시

이 문서는 계약 검사 결과만 모은 보고서가 아니다. 현재 코드, 현재 `engine-flow-*` 스크린샷, 1단원 1~4차시의 코드·문서·스크린샷을 항목별로 나란히 보고, 별 줍기에 빠진 부분을 판정한 기록이다.

## 판정 기준

- `✅ 통과`: 코드, 실제 화면, 문서 증거가 현재 흐름과 맞는다.
- `🟡 일부 통과`: 핵심 기능은 있으나 비교 차시보다 약하거나 증거가 부족하다.
- `❌ 부족`: 학생 배움이나 현재 검증의 신뢰도를 해치는 결손이다.
- `⏸ 선택`: 핵심 배움과 별개이고 제품·백엔드 결정이 필요한 항목이다.
- `P0`: 다음 배포 전에 고칠 문제
- `P1`: 다음 큰 수정 때 반드시 함께 고칠 문제
- `P2`: 완성도 향상 또는 선택 기능

## 비교 차시에서 가져올 강점

| 비교 차시 | 강점으로 삼은 부분 | 별 줍기에 그대로 복사하지 않을 부분 |
|---|---|---|
| 1-1 매스몬 상자런 | 정답과 오답이 보상 손익으로 이어지는 구조, 망가진 상자 피드백 | 문제 화면에 점수판·상자판을 동시에 크게 펼치는 과밀 구조 |
| 1-2 매스몬 로켓발사 대작전 | 계산 과정의 시각화, 연료와 목적지로 이어지는 진행감 | 계산판·힌트·로켓 상태를 한 화면에 모두 크게 두는 분할 구조 |
| 1-3 매스몬 10배 점프섬 | 현재 위치·다음 섬·마지막 섬이 보여 주는 `다음엔 더 멀리` | 섬 지도를 별 줍기 테마와 무관하게 그대로 옮기는 것 |
| 1-4 매스몬 로봇 합체 | 현재 단계만 크게 보여 주는 계산, 정답 반영, 생성 이미지 상태 세트, 검증·문서 완결성 | 로봇 부품과 합체 연출 자체 |

## 1. 배움 목표와 문제 모델

|---:|---|---|---|---|
| 1 | 차시 목표가 `나머지가 있는 나눗셈`에 직접 닿는가 | 모든 문제에서 `나누는 수×몫+나머지=처음 수`, `0<나머지<나누는 수`를 생성·검증한다. | ✅ | 유지 |
| 2 | 계산이 보상을 여는 도구인가 | 몫과 나머지를 모두 판단하고 완성식을 본 뒤 `별병 열기`로 이동한다. | ✅ | 유지 |
| 3 | 학생이 수학적으로 답을 결정하는가 | 몫 앞뒤 `q-1, q, q+1`을 비교하고, 남은 별 수를 한 번에 고른다. | ✅ | 유지 |
| 4 | 숫자를 보지 않고 반복 조작만 해도 끝나는가 | 이전의 별 반복 담기를 제거했다. 정답 경로의 수학적 판단과 문제 입력은 모두 문제당 2회이며 최소·중앙값·평균·최대가 2회다. | ✅ | 화면 이동·보상 열기와 수학 입력을 계속 분리해 기록 |
| 5 | 확인 버튼을 정답 탐색기로 쓸 수 없는가 | 몫과 나머지는 선택 즉시 판정한다. 작은 수부터 넣고 확인하는 반복 경로가 없다. | ✅ | 유지 |
| 6 | 그럴듯한 오답이 있는가 | 몫은 너무 작음·정답·너무 큼, 나머지는 실제 나머지와 나누는 수 주변 값으로 구성된다. | ✅ | 유지 |
| 7 | 오답이 수학적으로 구분되는가 | 너무 작으면 한 묶음을 더 만들 수 있고, 너무 크면 필요한 별이 모자란다는 관계를 모델이 계산한다. | ✅ | 유지 |
| 8 | 정답만으로 최고 결과가 쉽게 보장되지 않는가 | 정답은 유리하지만 사건 가중치와 별빛 변화가 따로 작동하고, 최고 결과는 정답 수와 별빛 조건을 함께 본다. | ✅ | 유지 |
| 9 | 틀려도 빈손이 아닌가 | 오답 사건에도 다음 문제로 진행하며 결과 장면과 재도전 경로가 남는다. 0별빛 결과 자산도 검증한다. | ✅ | 유지 |
| 10 | 최고 보상이 충분히 드문가 | 일반·희귀·전설 사건 가중치와 결과 문턱을 분리했고, 모델 QA가 희귀성·변동성을 검사한다. | ✅ | 가중치 변경 때 시뮬레이션 재실행 |

## 종합 판정

### 잘된 부분

- 현재 문제 화면은 1단원 1·2차시보다 덜 복잡하고, 3·4차시처럼 현재 단계와 선택지가 바로 보인다.
- 반복 담기를 없애고 몫의 경계를 비교하게 바꾼 점은 학생의 생각을 밖으로 드러낸다.
- 너무 작은 몫, 너무 큰 몫, 남은 별 오답을 서로 다른 수학 관계로 설명할 수 있다.
- 완성식을 본 뒤 학생이 별병을 여는 흐름, 랜덤 사건, 빈손 없는 결과는 시리즈 철학과 맞는다.
- 보상과 결과는 생성 장면을 중심으로 하며 텍스트와 패널을 과하게 겹치지 않는다.

### 해결한 필수 작업

1. **P0 — 설명 수량 관계:** v5 자산에서 10칸, 40개 관계, 남은 2개를 정확히 맞췄다.
2. **P1 — 결정적 화면 증거:** 양방향 몫 오답, 몫 정답 확인, 나머지 오답, 완성식을 두 화면 크기에서 각각 캡처한다.
3. **P1 — 검증 자료 최신성:** 예전 QA와 43개 캡처를 `_archive/`로 분리했다.
4. **P1 — `다음엔 더 멀리`:** 현재 별과 다음 별의 생성형 제목 이미지를 문제 HUD에 표시한다.
5. **P1 — 문서 완결성:** README·REPORT에 확률, 문턱, 입력 수, 증거, 제품 선택을 기록했다.

### 사용자 결정이 필요한 선택 항목

- **전국 순위 활성화 여부**: 1단원 1~4차시와의 기능 통일에는 도움이 되지만, 핵심 배움에는 필수는 아니다. 활성화하면 서버 검증·결과 ID·태블릿 순위 화면 QA까지 함께 작업해야 한다.

## 최종 결론

현재 별 줍기는 **학습 조작, 오답 피드백, 마지막 확인, 랜덤 보상, 진행감, 결과, 현재 증거**에서 비교 차시의 필수 기준을 통과했다. 문제 화면 밀도와 학생 판단은 1단원 1·2차시보다 간결하고, 3·4차시의 현재 단계 중심 흐름을 유지한다. 이번 감사에서 확인한 P0·P1은 모두 해결했다.
