## 구현 결과

문제 화면의 원천 구조를 `빈 계산 막대 + 작은 현재→다음 제목`에서 `상시 별자리판 + 실제 별 조작판`으로 교체했습니다.

- 왼쪽 `300×656px` 슬롯에는 여섯 단계 유니콘 별자리판이 항상 보입니다.
- 오른쪽에는 처음 수만큼 별이 10열 격자로 보입니다.
- 몫 보기는 곱한 결과를 큰 글자로, 묶음 수를 보조 글자로 보여 줍니다.
- 답을 고른 뒤에만 별이 최대 8열×4행의 묶음 캡슐로 바뀝니다.
- 작은 몫은 더 만들 수 있는 한 묶음, 큰 몫은 부족한 별자리를 현재 판에서 보여 줍니다.
- 나머지 단계에서는 이전 묶음을 접고 남은 별을 확대합니다.
- 마지막 식을 확인한 뒤 학생이 `별병 열기`를 눌러 보상으로 갑니다.

이 흐름으로 별·별병·유니콘자리는 배경 장식이 아니라 `나누기 → 나머지 → 별빛 → 결과`를 잇는 하나의 세계가 됐습니다.

## 수학·입력 계약

- 모든 생성 문제는 `처음 수 = 나누는 수×몫+나머지`를 만족합니다.
- 나머지는 항상 0보다 크고 나누는 수보다 작습니다.
- 몫 선택지는 `q-1`, `q`, `q+1`이고 각 보기의 곱과 차이를 모델이 함께 계산합니다.
- 최대 문제 밀도는 99개 흩어진 별과 32개 캡슐이며, 고정 계산판 안에 들어갑니다.
- 정답 경로의 수학 입력은 문제당 2회입니다.
- 몫 정답 확인은 1.2초 머물고, 마지막 완성식은 수동 보상 열기 전까지 유지됩니다.

모델 QA는 200개 시드×10문제를 검사해 수식, 나머지 범위, 선택지 곱, 부족 수, 오답 관계, 8×4 캡슐 경계를 확인했습니다.

## 계산과 보상의 연결

- 처음에 맞힌 경우 실제 나머지 개수만큼 별이 왼쪽 별병으로 이동합니다.
- 기존 `remainderBonus`와 이동 별 개수는 같은 `problem.remainder`를 씁니다.
- 랜덤 사건은 기존 확률과 문턱을 유지합니다.
- 보상 공개 뒤 실제 별빛 변화량 하나만 보여 줍니다.
- 보상이 반영되면 왼쪽 별자리 이미지가 즉시 새 단계로 바뀝니다.
- `prefers-reduced-motion`에서는 이동 애니메이션을 없애고 별병과 별자리 밝기 변화만 남깁니다.

## Humanizer 학생 문구 QA

첫 화면 목표, 설명, 문제 지시, 선택지, 오답, 정답 확인, 완성식, 보상, 결과 이름을 다시 읽었습니다.

- `6×몇이 47을 넘지 않을까요?`
- `6개씩 7묶음, 42개예요.`
- `한 묶음을 더 만들 수 있어요.`
- `별 1개가 모자라요.`
- `묶고 남은 별을 세어 봐요.`
- `6개면 한 묶음이에요.`

한 문장에는 행동 하나만 남겼습니다. `핵심`, `등급`, `게이트`, `오브젝트` 같은 제작자 말은 학생 화면에 없습니다. 설명 대체 문구의 피동형도 `남은 별을 별병에 담으면 유니콘자리가 빛나요.`로 고쳤습니다. 의미·수치·격식은 그대로 유지했습니다.

## 텍스트 넘침·요소 겹침 QA

- 화면 크기: `1280×800`, `1024×768`, `1780×1112`
- 확인 상태: 표지, 설정, 설명 1·2, 문제 대기, 20개·99개 별 경계, 32캡슐 경계, 몫 너무 작음·너무 큼·정답, 나머지 대기·오답·정답, 완성식, 보상 닫힘·열림, 여섯 결과, 순위판
- 결과: 텍스트 overflow 0건, 깨진 이미지 0건, 별자리판과 계산판 교차 0px
