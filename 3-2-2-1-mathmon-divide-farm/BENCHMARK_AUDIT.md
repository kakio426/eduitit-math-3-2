# 3-2-2-1 매스몬 나누기 농장 기준 차시 비교 감사

- 감사일: 2026-07-14
- 비교 대상: 3학년 2학기 1단원 1·2·3·4차시
- 현재 판정: **필수 계약 통과**
- 판정: `통과` / `일부 통과` / `부족` / `선택`

## 1. 기준 차시별 비교

| 기준 차시 | 비교한 강점 | 농장 반영 | 판정 |
|---|---|---|---:|
| 1-1 상자런 | 계산 직후 랜덤 손익이 보이고 다음 보상을 기대함 | 문제마다 수확 바구니를 직접 열고 증가·감소·0·희귀 도약이 나옴 | 통과 |
| 1-2 로켓발사 | 자리값 단계가 왜 필요한지 계산 안에서 이어짐 | 십의 자리 몫 → 일의 자리 몫 → 두 수를 합친 전체 몫을 화면과 설명에 연결 | 통과 |
| 1-3 점프섬 | 지금 위치와 마지막 목표가 이어짐 | 상단 `1/10`, 문제 뒤 수확, 10문제 뒤 농장 결과로 최소 진행 단서 유지 | 통과 |
| 1-4 로봇 합체 | 현재 판단만 크게 보여 주고 값 반영 뒤 보상으로 이동 | 한 화면 한 입력, 바구니 반영, 마지막 완성식, 학생이 누르는 `수확 보기` | 통과 |

한 차시를 통째로 복제하지 않았다. 1-1의 보상 루프, 1-2의 단계 이유, 1-3의 진행감, 1-4의 확인 흐름만 가져왔다.

## 2. 강제 체크리스트

| 항목 | 판정 | 현재 증거 |
|---|---:|---|
| 한 화면 한 행동 | 통과 | 현재 단계의 숫자판 하나만 조작 |
| 학생의 수학적 판단 | 통과 | 한 바구니의 실제 값을 학생이 먼저 입력 |
| 반복 조작이 정답을 대신하지 않음 | 통과 | 답 확정 뒤에만 시스템이 모든 바구니를 채움 |
| 단계의 존재 이유 | 통과 | 십의 자리 몫, 일의 자리 몫, 한 바구니 전체 수를 별도 줄로 표시 |
| 그럴듯한 오답 | 통과 | 실제보다 적거나 많은 한 바구니 값을 만들 수 있음 |
| 오답 이유의 시각화 | 통과 | 학생 값이 모든 바구니에 들어가고 `남아요`·`부족해요`로 비교 |
| 실제 값 표현 | 통과 | 10개 묶음 2개를 답 `2`가 아니라 `20`으로 입력·확인 |
| 정답 확인 머무름 | 통과 | 바구니가 채워진 확인 화면 뒤 다음 단계로 이동 |
| 마지막 완성값 | 통과 | `30 + 4 = 34`, `68 ÷ 2 = 34`를 보상 전에 표시 |
| 텍스트 넘침·요소 겹침 0건 | 통과 | 3개 화면 크기 흐름 QA |
| 랜덤 보상 | 통과 | 증가·감소·0·희귀 사건 유지 |
| 빈손 금지 | 통과 | 정답 0개도 씨앗 결과와 다시 버튼이 있음 |
| 다음엔 더 멀리 | 통과 | 6단계 농장 결과와 희귀 황금밭 |

## 3. 화면별 확인

### 첫 화면

- [x] 제목, 한 줄 목표, 시작 버튼이 먼저 보인다.
- [x] 생성형 배경·제목·시작 버튼 자산을 쓴다.
- [x] `똑같이 나눠 농장을 키워요.`가 계산과 게임 목표를 연결한다.
- [x] 16:10 Stage 안에 브랜드·단원·설정 버튼이 있다.

### 설명 1 — 풀이 이유

- [x] `48 ÷ 4` 한 예시만 사용한다.
- [x] 10개 묶음 4개가 `40`임을 수량으로 맞췄다.
- [x] 낱개 당근 8개가 `8`임을 수량으로 맞췄다.
- [x] `40 ÷ 4 = 10`이 십의 자리 몫을 만든다는 이유가 보인다.
- [x] `8 ÷ 4 = 2`가 일의 자리 몫을 만든다는 이유가 보인다.
- [x] `10 + 2 = 12`가 한 바구니의 전체 몫으로 이어진다.
- [x] 설명 이미지·식·물건 수가 실제 수학 관계와 맞다.

### 설명 2 — 보상 목표

- [x] 문제를 풀면 수확이 달라짐을 알린다.
- [x] 10문제 뒤 농장을 본다는 마지막 목표가 있다.
- [x] 보상은 설명 뒤 기본 화면에 펼쳐 두지 않고 문제 뒤에 직접 연다.

### 십의 자리 값 나누기

- [x] `먼저 60을 바구니 3개에 똑같이 나눠요.`처럼 실제 값을 말한다.
- [x] 학생이 답하기 전 바구니는 비어 있고 `?`만 보인다.
- [x] 학생은 한 바구니의 실제 값 `20`을 입력한다.
- [x] `2묶음`을 답으로 받지 않는다.
- [x] 적은 답은 남는 전체 수를 보여 준다.
- [x] 많은 답은 부족한 전체 수를 보여 준다.
- [x] 10의 배수가 아니면 `10개 묶음으로 나눠요.`라고 짧게 안내한다.
- [x] 정답 뒤에만 묶음 이미지가 바구니 수만큼 차곡차곡 놓인다.

### 낱개와 전체 몫

- [x] 낱개 전체를 같은 바구니 수로 나눈다.
- [x] 학생이 일의 자리 몫을 직접 입력한다.
- [x] 정답 확인에서 앞 단계 묶음과 낱개가 함께 보인다.
- [x] 마지막에는 두 수를 합쳐 몫을 숫자로 쓴다.
- [x] 몫 오답 뒤 현재 바구니를 다시 볼 수 있다.
- [x] 마지막 정답은 완성식과 함께 충분히 보인다.

### 보상과 결과

- [x] 보상창이 마지막 정답 확인을 즉시 덮지 않는다.
- [x] 닫힌 보상창은 이미지와 `열기`만 보인다.
- [x] 열린 보상창은 이미지·변화량·`다음`만 보인다.
- [x] 정답을 많이 맞힐수록 유리하지만 랜덤 손익을 유지한다.
- [x] 낮은 결과도 빈 화면이 아니고, 최고 결과는 희귀하다.
- [x] 희귀 최고 결과의 다음 목표가 낮은 단계로 되돌아가지 않는다.

## 4. 판단 수와 입력 수

| 항목 | 이전 목적지 선택 | 현재 입력 방식 |
|---|---:|---:|
| 수학적 판단 | 목적지 선택을 여러 번 반복 | 십의 자리 몫·일의 자리 몫·전체 몫 3번 |
| 최소 입력 | 13회 | 8회 |
| 중앙값 | 29회 | 8회 |
| 평균 | 26.7회 | 8회 |
| 최대 입력 | 41회 | 8회 |

현재 8회는 `두 자리 답+확인 3회`, `한 자리 답+확인 2회`, `두 자리 몫+확인 3회`다. 같은 뜻의 물건 배치를 반복하지 않는다.

## 5. 문구 Humanizer 점검

| 문구 | 판정 | 이유 |
|---|---:|---|
| `한 바구니에 몇 개씩인지 써요.` | 통과 | 학생 행동이 바로 보임 |
| `먼저 60을 바구니 3개에 똑같이 나눠요.` | 통과 | 실제 값과 목적지가 분명함 |
| `십의 자리 몫을 만들어요.` | 통과 | 현재 단계의 이유를 짧게 말함 |
| `20개가 남아요.` | 통과 | 적은 답의 결과를 현재 물건과 연결 |
| `20개가 부족해요.` | 통과 | 많은 답의 결과를 현재 물건과 연결 |
| `두 수를 더해 몫을 써요.` | 통과 | 마지막 행동 하나만 말함 |

`핵심`, `메커니즘`, `부분몫`, `게이트`, `적용` 같은 제작자 말을 학생 화면에 쓰지 않았다.

## 8. 제품 선택

- 전국 순위: **선택(P2)**. 백엔드 계약과 별도 동적 UI 화면이 필요하므로 이번 핵심 학습 수정에 넣지 않았다.
- 문제 화면 수확판: **선택하지 않음**. 보상 목표는 설명과 문제 뒤 `수확 보기`로 충분히 연결하고, 현재 판단을 가릴 추가 패널은 두지 않았다.

필수 P0/P1은 모두 수정했다. 남은 항목은 학습 결함이 아니라 제품 범위 선택이다.
