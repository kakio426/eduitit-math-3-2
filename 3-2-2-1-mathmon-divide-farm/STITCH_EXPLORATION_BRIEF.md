# Stitch 탐색 브리프 — 매스몬 나누기 농장

## 이 문서의 역할

이 문서는 Stitch가 `매스몬 나누기 농장`의 학생 화면을 새로 탐색하기 위한 **학습·제품 브리프**다. 현재 화면의 카드, 드래그 영역, 숫자판, 프레임, 배경 배치, 색, 글꼴, 비율을 복제하거나 고치라는 문서가 아니다.

Stitch는 아래의 학습 목적과 상태 계약만 지키며, 화면 구성, 시각 언어, 조작 방식, 농장 세계의 표현, 전환 방식을 독자적으로 판단한다. 현재 구현의 화면 구조는 참고 기준이 아니며, 특히 다음을 그대로 가져오지 않는다.

- 빈 바구니에 카드를 끌어다 놓는 방식
- 네 개의 설명이 긴 선택 카드
- 큰 숫자 패드
- 한 화면에 문제·해설·보상·다음 목표를 모두 펼치는 구성
- 장식 때문에 수학 행동이 좁아지는 좌우 분할 레이아웃

## 제품 맥락

- 시리즈: 에듀잇티 매스몬 수학 게임
- 대상: 초등학교 3학년
- 단원: 3학년 2학기 2단원 나눗셈
- 이번 차시: 1차시, **내림 없는 두 자리 수 ÷ 한 자리 수**
- 테마: 농장에서 채소를 똑같이 나누고, 문제를 풀수록 내 농장이 자란다.
- 실행 환경: 태블릿 가로와 컴퓨터. 기본 Stage는 16:10, 기준 크기는 1280×800이다. 스마트폰 세로는 이번 탐색 범위 밖이다.

## 학생이 이해해야 하는 수학

예시 문제 `88 ÷ 4`에서 학생은 다음 관계를 스스로 이해해야 한다.

1. `80`은 10개 묶음 `8묶음`으로 볼 수 있다.
2. `8묶음`을 4곳에 똑같이 나누면 한 곳에는 `2묶음`이 들어간다. 이것은 `20`이다.
3. 남은 `8개`를 4곳에 똑같이 나누면 한 곳에는 `2개`가 들어간다.
4. 한 곳의 결과는 `20 + 2 = 22`이고, 그래서 `88 ÷ 4 = 22`이다.

핵심은 답 `22`를 빠르게 맞히는 것이 아니라, **십의 자리와 일의 자리를 따로 똑같이 나누면 왜 한 바구니의 수가 만들어지는지** 학생이 눈으로 보고 말할 수 있게 하는 것이다.

문제 은행은 20~99 사이의 내림 없는 정확한 나눗셈이다. 나누는 수는 2~5이며, 십의 자리와 일의 자리가 모두 나누어떨어진다. 문제마다 실제 수와 바구니 수만 바뀌고 학습 구조는 같다.

## 학습 경험 원칙

Stitch는 아래 결과를 만드는 조작을 설계한다. 특정 UI 패턴은 정해져 있지 않다.

### 반드시 일어나야 하는 일

- 학생은 현재 화면에서 해야 할 **한 가지 수학 행동**을 3초 안에 알아차린다.
- 학생은 숫자, 양, 위치, 관계, 순서 중 적어도 하나를 실제로 판단해서 답을 만든다.
- 십의 자리와 일의 자리는 각각 독립된 판단이다. 두 판단이 끝난 뒤 이미 결정된 전체 몫을 다시 고르게 하거나 입력시키지 않는다.
- 학생의 선택 전에는 시스템이 정답 분배를 미리 보여 주지 않는다.
- 정답 후에는 학생이 고른 값이 실제 수량 관계의 어디에 들어가는지 보이고, 그 다음 단계로 넘어간다.
- 틀린 답은 단순한 빨간 표시가 아니라 ‘남는지’ 또는 ‘더 필요한지/많은지’를 현재 수량 관계로 이해할 수 있게 한다. 학생은 자동 초기화되지 않고 생각을 고칠 수 있어야 한다.
- 확인은 완성한 생각을 검증하는 역할이다. `1부터 넣고 확인 → 2를 넣고 확인`으로 정답을 탐색하게 만들면 안 된다.
- 같은 뜻의 옮기기·누르기를 여러 번 반복해서 끝나는 구조는 피한다. 반복이 필요하다면 각 입력마다 새 수학 판단이 생겨야 한다.

### Stitch가 자유롭게 정할 수 있는 것

- 학생이 답을 만드는 입력 방식: 교구 조작, 수량 구성, 비교, 선택, 배치, 빈칸 구성, 다른 자연스러운 방식
- 처음에 보이는 실제 물건과 정답 뒤에 펼쳐지는 전체 관계의 차이
- 농장 배경의 존재감, 작업대의 형태, 바구니와 채소의 시각적 표현
- 문제식, 수량, 조작 영역, 피드백의 화면상 관계와 전환 방식
- 고정된 화면에 맞춘 정보량, 글자 위계, 애니메이션, 시각적 질감

## 화면 세트

Stitch는 아래 상태가 하나의 게임 경험처럼 이어지도록 설계한다. 화면 수를 기계적으로 늘리거나 줄이기보다, 각 상태가 학생에게 필요한 이유를 갖도록 판단한다.

### 1. 시작

- 게임 이름: `매스몬 나누기 농장`
- 학생이 오늘 무엇을 하는지 알 수 있는 짧은 목표
- 바로 시작할 수 있는 하나의 주 행동
- 브랜드, 단원 정보, 설정은 주 행동보다 조용해야 한다.

### 2. 방법 이해

- 학생이 왜 `십의 자리`와 `일의 자리`를 나누어 다루는지, 그리고 이번 게임에서 무엇을 만들거나 판단하는지 알게 한다.
- 사용법 설명만 하지 말고, 현재 단계의 값이 최종 답 `20 + 2 = 22`에 어떻게 이어지는지 보여 준다.
- 실제 문제와 같은 수량 관계를 쓴다. 장식 그림의 묶음 수와 식이 다르면 안 된다.

### 3. 성장 목표 이해

- 한 판은 10문제다.
- 문제를 해결하면 농장이 자라며, 마지막에 이번 농장을 확인한다.
- 성장 순서는 `씨앗 → 새싹 → 텃밭 → 농장 → 대농장 → 알 수 없는 특별 목표`다.
- 정답이 유리하지만 최고 농장이 보장되지는 않는다는 기대감을, 긴 규칙 설명 없이 이해할 수 있게 한다.

### 4. 문제: 십의 자리

- 큰 문제식과 현재 나눌 양, 바구니 수, 학생의 현재 판단이 서로 바로 연결된다.
- 예: `88 ÷ 4`의 첫 행동은 `80` 또는 `10개 묶음 8개`를 4곳에 같은 양으로 나누는 판단이다.
- 현재 단계가 최종 몫의 `20`과 연결된다는 이유가 화면에서 보인다.
- 문제 풀이 중에는 현재 농장 상태만 작게 보인다. 수확 숫자, 다음 단계, 성장 경로를 펼쳐 놓지 않는다.

### 5. 십의 자리 오답과 정답 확인

- 오답: 학생이 만든 상태와 남거나 넘친 이유를 짧고 명확하게 보여 준다.
- 정답: 선택한 양이 같은 바구니들 또는 동등한 수량 관계에 반영되고, `20`이 만들어졌음을 볼 수 있다.
- 정답 확인이 다음 화면이나 보상에 즉시 가려지지 않는다.

### 6. 문제: 일의 자리

- 십의 자리 결과는 작고 안정된 완료 흔적으로 남고, 일의 자리 판단이 새 중심이 된다.
- 예: 남은 `8개`를 4곳에 똑같이 나누어 한 곳의 `2개`를 만든다.
- 십의 자리에서 했던 판단과 같은 원리가 반복됨을 느끼되, 화면을 복제한 것처럼 지루하지 않게 한다.

### 7. 한 바구니 완성

- 두 판단의 결과가 한 바구니의 실제 수 `20 + 2 = 22`로 결합되는 순간을 보여 준다.
- 이어서 `88 ÷ 4 = 22`라는 완성식을 충분히 읽을 수 있게 한다.
- 이미 결정된 `22`를 다시 입력시키지 않는다.
- 이후 학생이 실제로 알 수 없는 보상을 열기 위한 행동만 남긴다.

### 8. 보상 열기

- 문제 화면 위 팝업이 아니라, 농장 변화가 중심인 독립된 보상 경험이다.
- 닫힌 바구니를 열기 전과 후의 두 상태가 분명해야 한다.
- 보상은 이번 농장에 실제 변화를 만든다. 숫자 변화만 주인공이 되지 않는다.
- 보이는 문구는 한 번에 짧은 결과 하나면 충분하다. 현재 변화와 다음 목표는 이어지되, 설명문처럼 길어지지 않는다.
- 빠르게 두 번 눌러도 보상이 한 번만 적용되어야 한다.

### 9. 다음 문제

- 보상을 본 뒤에는 다음 문제로 자연스럽게 돌아간다.
- 새로운 문제에서는 이전 풀이 정보가 학습을 방해하지 않는다.
- 현재 농장만 작게 이어져 ‘내가 무엇을 위해 풀고 있는지’가 살아 있어야 한다.

### 10. 최종 결과

- 10문제 뒤에는 점수표보다 **완성된 농장 장면**이 먼저 보인다.
- 가능한 결과: 씨앗, 새싹, 텃밭, 농장, 대농장, 특별한 황금밭.
- 각 결과는 실제 농장 모습이 뚜렷이 달라야 한다.
- 정답 수, 다음에 노릴 목표, 다시 하기, 전국 순위로 가는 길이 있어야 한다.
- 낮은 결과도 실패나 빈손처럼 보이지 않고, 다음에 더 키울 농장으로 느껴져야 한다.

### 11. 보조 화면

- 설정: 배경 소리, 효과 소리, 방법 다시 보기, 처음부터, 닫기
- 전국 순위: 여러 사람의 동적 기록을 정확하게 읽어야 하는 화면이다. 장면 이미지는 분위기만 맡고, 순위·이름·점수·버튼은 정확한 UI로 다룬다.

## 보상 세계의 사실

- 중심 보상은 하나다: **내 농장의 성장**.
- 문제는 10개다.
- 보상은 매 문제 뒤 무작위 사건으로 일어난다. 일반 수확, 벌레, 대풍작, 황금 당근, 빈 바구니, 매우 희귀한 황금밭이 있다.
- 최고 결과는 정답만으로 확정되지 않지만, 정답을 많이 맞힐수록 평균적으로 더 좋은 농장에 닿는다.
- 문제 풀이 화면에서는 수치 게이지나 성장 경로를 전면에 내세우지 않는다. 보상과 결과 화면에서만 이번 변화와 다음 기대를 보여 준다.

## 시각·문구 제약

- 학생에게 보이는 한국어는 초3이 소리 내어 읽어도 자연스러워야 한다. 한 문장에는 행동 하나만 둔다.
- 학생 화면에 `시스템`, `모드`, `게이트`, `이벤트`, `토큰`, `메커니즘` 같은 제작자 말은 쓰지 않는다.
- 수학 표현은 학교에서 쓰는 말과 자리값을 따른다. `20`, `80`처럼 실제 수를 쓰고 `2십`, `8십` 같은 표현은 피한다.
- 큰 문제, 현재 수학 행동, 선택/조작 영역이 장식·진행도·배지보다 먼저 보인다.
- 학습에 필요한 물건과 배경 장식이 같은 것을 중복해서 보여 주지 않는다. 실제 수량은 학생 조작과 함께 나타나는 물건만으로 읽힌다.
- 배경은 분위기를 만들 수 있지만 수학 화면의 폭·대비·읽기 순서를 빼앗으면 안 된다.
- 문구, 숫자, 이미지, 버튼, 상자 사이에는 의도하지 않은 겹침·잘림·충돌이 없어야 한다.

## 구현에 넘길 상태 계약

Stitch 결과를 구현으로 옮길 때 유지해야 하는 기술·동작 조건이다. 디자인의 답을 지정하는 목적이 아니다.

- 모든 화면은 16:10 Stage에서 성립해야 하며, 1280×800, 1024×768, 918×897에서 읽고 누를 수 있어야 한다.
- 학생 조작부는 최소 42×42px 이상의 터치 영역을 가진다.
- 대기, 오답, 정답 확인, 다음 단계, 마지막 완성식, 보상 닫힘/열림, 결과의 각 상태는 독립 화면으로 검증한다.
- 상태가 바뀌어도 핵심 문제 영역이 다른 열로 튀거나 폭이 급격히 줄지 않는다.
- 정답 확인에서는 선택한 값이 계산판·수량·물건에 먼저 반영되고, 그 뒤에 전환된다.
- `prefers-reduced-motion`에서는 이동 애니메이션 대신 이미지 교체와 밝기 변화 같은 차분한 전환을 제공한다.
- 설정 버튼은 모든 화면에서 같은 상단 보조 위치를 유지하며, 학습 영역과 겹치지 않는다.
- 결과 등급과 농장 장면은 유한한 생성 이미지 세트로 연결할 수 있고, 정답 수처럼 동적인 값만 정확한 UI 오버레이로 처리한다.

## Stitch에 기대하는 산출

아래를 설계 탐색의 결과로 제안한다.

1. 하나의 일관된 학생 경험을 이루는 화면 세트
2. 십의 자리와 일의 자리에서 학생이 각각 무엇을 판단하고, 화면이 그 판단을 어떻게 드러내는지에 대한 짧은 상태 설명
3. 오답, 정답 확인, 완성식, 보상 전후가 어떻게 달라지는지
4. 정보 우선순위: 학생이 처음 3초에 보는 것, 그다음 보는 것, 평소에는 조용히 남는 것
5. 16:10 컴퓨터·태블릿 가로에서 유지되는 조밀하지 않은 구성 원리

Stitch는 현재 구현을 다듬는 수준에 머물지 말고, 이 브리프의 학습 경험을 가장 분명하게 만드는 화면 언어를 새로 판단해 제안한다.
