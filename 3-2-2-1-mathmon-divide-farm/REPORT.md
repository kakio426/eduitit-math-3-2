## 이번 수정 결과

- 채소마다 목적지를 누르던 13~41회 반복 조작을 폐기했습니다.
- 학생이 `한 바구니에 몇 개씩`인지 먼저 숫자로 답하게 했습니다.
- 답을 내기 전에는 빈 바구니만 보이고, 정답을 확정한 뒤에만 생성형 채소 이미지가 모든 바구니에 놓입니다.
- 십의 자리 단계는 묶음 수 `2`가 아니라 실제 값 `20`을 입력·확인합니다.
- 오답은 학생이 쓴 양을 모든 바구니에 보여 주고, 전체보다 적으면 `남아요`, 많으면 `부족해요`로 비교합니다.
- 각 단계에 `십의 자리 몫`, `일의 자리 몫`, `한 바구니의 전체 수`라는 존재 이유를 연결했습니다.
- 첫 설명은 `40 ÷ 4 = 10`, `8 ÷ 4 = 2`, `10 + 2 = 12`로 단계 관계를 보여 줍니다.
- 문제 화면 상단에 브랜드·단원·문제 수를 복구하되, 수확판은 펼치지 않아 한 행동 집중을 유지했습니다.
- 정답 확인 화면은 생성형 빈 바구니·10개 묶음·낱개 이미지를 실제 DOM에 쌓아 보여 줍니다. CSS 도형으로 바구니나 채소를 그리지 않습니다.
- 채소 묶음은 카드 전체 폭이 아니라 바구니 원본의 640:426 장면 안에 배치해, 넓은 화면에서도 바구니 밖으로 튀어나오지 않습니다.
- 오디오 QA에 `getPrefs()`와 `setPrefs()`를 추가하고 공용 localStorage 키를 검증합니다.
- 희귀 최고 결과가 낮은 다음 결과를 가리키던 `getNextResult` 경계도 수정했습니다.

## 수학 계약

- 십의 자리 값과 일의 자리 값이 각각 나누어떨어집니다.
- 일의 자리 수가 0인 문제는 제외합니다.
- 나누는 수는 2~5이고, 화면 바구니 수와 같습니다.
- 십의 자리 답 × 바구니 수 = 십의 자리 실제 값입니다.
- 일의 자리 답 × 바구니 수 = 낱개 전체입니다.
- 두 답의 합은 원래 나눗셈의 몫과 같습니다.
- 한 판은 중복 없는 10문제입니다.
- 학생은 십의 자리 몫, 일의 자리 몫, 전체 몫을 각각 한 번 판단합니다.
- 정답 경로 입력은 모든 문제에서 8회입니다.

## Humanizer 학생 문구 QA

확인한 문구:

- `한 바구니에 몇 개씩인지 써요.`
- `먼저 60을 바구니 3개에 똑같이 나눠요.`
- `십의 자리 몫을 만들어요.`
- `이제 6개를 바구니 3개에 똑같이 나눠요.`
- `일의 자리 몫을 만들어요.`
- `몇 개씩 넣을지 써요.`
- `20개가 남아요.`
- `20개가 부족해요.`
- `10개 묶음으로 나눠요.`
- `두 수를 더해 몫을 써요.`
- `문제를 풀면 수확이 달라져요. 10문제 뒤 농장을 봐요.`

제작자 용어, 번역투, 긴 명사 나열을 쓰지 않았습니다. 한 문장에는 한 행동만 두고, 화면 속 바구니·채소·수로 바로 확인할 수 있는 말만 남겼습니다.

## 텍스트 넘침·요소 겹침 QA

- 화면 크기: `1280×800`, `1024×768`, `918×897`
- 확인 상태: 표지, 설정, 설명 1·2, 십의 자리 대기, 적음/많음 오답, 십의 자리 정답 확인, 일의 자리 대기·정답 확인, 몫 입력·오답, 마지막 확인, 완성식, 닫힌 보상, 열린 보상, 결과
- 결과: 넘침 0건, 의도하지 않은 겹침 0건, Stage 밖 조작부 0건, 깨진 이미지 0건
- 문제 화면 브랜드·단원·문제 수·설정 버튼이 같은 상단 줄에서 서로 겹치지 않음을 확인했습니다.
- 생성형 바구니와 채소가 동적 상태에서도 로드되고, 학생이 답하기 전에는 정답 배치가 나타나지 않음을 확인했습니다.
- 바구니에 채소가 쌓이는 십의 자리·일의 자리 확인 상태를 세 화면 크기에서 각각 따로 캡처했습니다.
