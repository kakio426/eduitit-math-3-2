## 2026-07-13 Codex 브라우저 문제 화면 수정

- `dvh`를 해석하지 못하는 브라우저에서도 Stage가 가로폭만 따라 커지지 않도록 `vh` contain 폴백을 먼저 선언했습니다.
- 긴 나눗셈 괄호선과 위쪽 몫 칸의 테두리가 겹치지 않도록 SVG 기준선을 다시 배치했습니다.
- SVG `<title>` 툴팁을 제거하고 같은 계산판 설명은 `aria-label`로 유지했습니다.
- 큰 문제의 숫자와 `÷` 사이 간격을 안정시키고 흰 그림자를 제거했습니다.
- 선택지 라벨을 `몫`과 `남은 십`으로 줄여 현재 행동과 바로 이어지게 했습니다.
- 선택지의 라벨과 숫자를 각 반쪽 카드 중앙의 한 묶음으로 정렬하고, 숫자 폭은 tabular 숫자로 고정했습니다.
- 첫 단계 정답 확인에서 `나누는 수×몫`을 십의 자리 아래에 쓰고 빼는 선과 남은 십을 보여 줍니다.
- 다음 단계에서는 일의 자리 수가 같은 열을 따라 수직으로 내려오며, 남은 십과 나란히 놓여 내린 수를 만듭니다.
- 첫 단계 확인은 1.8초, 내림 확인은 1.6초 동안 보여 주어 계산판 변화와 확인 문구를 읽을 시간을 줍니다.
- 원본 `view.js`·`lesson.css`와 배포 `index.html`을 같은 구조로 맞춰 재빌드해도 계산판이 되돌아가지 않게 했습니다.
- 좁거나 낮은 창에서는 계산판·지시문·선택지 높이를 함께 다시 배분해 정답 확인 화면을 가리지 않게 했습니다.
- 문제 화면 왼쪽 위의 `에듀잇티 수학 게임` 배지와 오른쪽 위의 `2단원 나눗셈` 배지를 공통 상단 슬롯에 복원했습니다.

## 수학 계약

- 모든 문제에서 남은 십이 1개 이상 생깁니다.
- `남은 십×10+일의 자리=내린 수`가 항상 성립합니다.
- 내린 수는 나누는 수로 나누어떨어집니다.
- 십의 자리 몫·남은 십 선택지는 두 값을 글자로 구별합니다.

## Humanizer 학생 문구 QA

- `70에서 십의 자리 몫과 남은 수를 골라요.`처럼 학생이 평소 쓰는 수로 말합니다.
- 첫 단계 선택지는 십의 자리 숫자 `2`, `1`만 쓰지 않고 `몫 20`, `남은 수 10`처럼 실제 값을 보여 줍니다.
- `남은 10과 일의 자리 6을 합친 수를 내려요.`처럼 실제로 고를 수를 정확히 말합니다.
- 설명 화면도 `남은 수와 일의 자리 수를 합쳐요.`로 맞춰 문제 화면과 같은 순서로 안내합니다.
- `10 ÷ 2의 몫을 골라요.`처럼 내린 수와 나누는 수를 함께 보여 줍니다.
- 숫자에 따라 조사가 어색해지던 확인 문구는 `남은 십 1 · 일의 자리 0 → 10` 구조로 바꿨습니다.
- 오답 피드백에 남아 있던 `2십`, `…십이라` 같은 표현도 `20`, `곱하면 40이라 30보다 커요.`처럼 실제 수로 짧게 바꿨습니다.
- 닫힌 보상 문구는 버튼의 `열기`를 되풀이하지 않는 `어떤 힘이 나올까요?`로 정리했습니다.
- `핵심`, `이벤트`, `등급`, `게이트` 같은 제작자 말과 숫자+`십` 표기가 학생 화면 동적 문구에 0건임을 다시 검색했습니다.

## 2026-07-14 비교 감사 후 수정

- 몫을 크게 또는 작게 고르면 고른 몫이 붉은 몫 칸에 들어가고, 곱한 값과 실제로 남는 수가 계산판에 나타납니다.
- 남은 수 내림 오답은 계산판의 `남은 십 + 일의 자리`와 학생이 고른 수를 나란히 보여 줍니다.
- 마지막 몫 오답은 고른 몫을 몫 칸에 넣고 `나누는 수×고른 몫`을 계산판 안에서 바로 확인합니다.
- 상단에 `지금 지하 → 다음 1층 → 끝 꼭대기`를 보여 주고, 힘과 정답 수가 바뀌면 현재·다음 층도 함께 바뀝니다.
- 최저 결과를 `다시 준비`에서 `지하 정비층`으로 바꿔 `0/10`이어도 도착지가 남습니다.
- 현재 DOM과 엔진 흐름을 쓰는 `scripts/qa-lesson2-elevator.mjs`로 전용 QA를 교체했습니다.
