# 매스몬 검산 자물쇠 설명 보고서

## 1. 개요

`매스몬 검산 자물쇠`는 3학년 2학기 2단원 4차시에서 다루는 곱셈을 이용한 나눗셈 검산을 게임 흐름으로 연습하는 에듀잇티 수학 게임입니다. 학생은 나눗셈 결과의 몫과 나머지를 사용해 원래 나누어지는 수가 맞는지 확인합니다.

핵심 목표는 `몫 × 나누는 수 + 나머지 = 나누어지는 수` 관계를 눈에 보이는 자물쇠 계산판으로 반복하게 만드는 것입니다.

## 2. 학습 설계

- 문제 유형: 나머지가 있는 두 자리 수 ÷ 한 자리 수의 검산
- 문제 은행: 나누는 수 2~9, 몫 4~18, 나머지 1~나누는 수보다 작은 수로 생성
- 라운드 길이: 10문제
- 입력 방식: 곱하기, 나머지 더하기, 원래 수 확인 3단계 4지선다 선택
- 1단계: `몫 × 나누는 수` 값을 골라 곱한 값을 만든다.
- 2단계: 곱한 값에 `나머지`를 더해 원래 수를 복원한다.
- 3단계: `검산 결과 = 원래 수` 비교식 중 맞는 식을 고른다.
- 오답 설계: `몫 × 나누는 수`에서 멈추는 나머지 더하기 누락 오답을 2단계와 3단계 보기에 포함한다.
- 보상: 한 문제 완료마다 금고 여는 힘 이벤트를 1회 적용한다.
- 결과 이름: 금고 여는 힘과 정답 수 조건을 함께 사용해 자물쇠, 금고, 대형금고, 비밀금고, 보물고 중 하나를 공개한다.
- 비밀 결과: 무지개 코어를 얻으면 전설 금고가 열린다.
- 최종 보상: 도달한 금고 이름 자체가 보상이며, 매스몬 도감 수집 구조는 사용하지 않는다.

### 교육적 의도

검산은 답을 다시 맞혀 보는 절차가 아니라, 나눗셈의 구조를 확인하는 방법입니다. 이 게임은 `47 ÷ 5 = 9 ... 2`를 `9 × 5 = 45`, `45 + 2 = 47`로 나누어 보여 줍니다. 특히 나머지를 더하지 않고 `45`에서 멈추는 선택지를 반복적으로 넣어, 검산식의 마지막 `+ 나머지`가 왜 필요한지 행동으로 확인하게 했습니다.

보상은 `금고 여는 힘` 하나로 단일화했습니다. 정답을 많이 맞히면 분명히 유리하지만, 보상 이벤트에는 증가, 감소, 다시 잠김, 마스터키, 무지개 코어가 섞여 있어 매 판 결과가 달라집니다. 틀렸던 문제는 오류 처리 이벤트만 적용해 일부러 틀리는 전략을 막습니다. 플레이 중에는 도달 금고 이름을 미리 강조하지 않고, 금고 주변 빛과 잠금등만 힘에 따라 켜지게 했습니다.

## 3. 게임 흐름

```text
첫 화면 -> 설명 화면 -> 곱하기 -> 나머지 더하기 -> 원래 수 확인 -> 금고 여는 힘 이벤트 -> 다음 문제 또는 결과 -> 금고 이름 공개
```

학생은 먼저 몫과 나누는 수를 곱합니다. 다음에는 곱한 값에 나머지를 더합니다. 마지막으로 `47 = 47`, `45 = 47`처럼 검산 결과와 원래 수를 비교한 식을 보고 맞는 식을 고릅니다.

## 4. 화면별 설명

### 첫 화면

첫 화면은 킹드래곤몬이 금고방 조명과 바닥 그림자 안에 함께 들어간 `cover-generated.webp`를 RasterStage 배경으로 사용합니다. 커버 위에는 별도 `.cover-mathmon` HTML 이미지를 얹지 않습니다. 게임 제목은 GPT Image/imagegen으로 만든 `title-logo-generated.webp` 독립 래스터 오버레이이며, 실제 제목은 `visually-hidden` 텍스트로 남겼습니다. 시작 버튼은 `start-button-source.png`, `start-button-generated.png`, `start-button-generated.webp` 생성형 버튼 아트를 쓰는 `data-cover-start-standard="generated-button-art"` 구조입니다.

### 설명 화면

설명 화면은 `tutorial-page-1-generated.webp`, `tutorial-page-2-generated.webp` 2장 생성 이미지가 보이는 문구와 버튼 표면을 담당합니다. HTML은 접근성용 숨김 텍스트와 투명 `tutorialBackButton`/`tutorialNextButton` hitbox만 맡습니다.

1쪽은 `어떻게 풀어요?`로 나눈 답을 곱하고 나머지를 더해 처음 수와 맞는지 보는 흐름을 보여 줍니다. 2쪽은 `무엇을 얻어요?`로 10문제, 금고 여는 힘, 금고 이름 결과를 보여 줍니다. 보이는 버튼은 이미지 안의 `다음`, `이전`, `계속하기`입니다.

### 문제 화면

문제 화면은 왼쪽에 보안실 배경과 금고 여는 힘, 오른쪽에 나눗셈 결과와 검산 계산판을 둡니다. 문제와 선택지가 가장 크게 보이도록 배경 이미지는 보조 역할로 제한했습니다.

검산 계산판은 1단계 곱하기, 2단계 나머지 더하기, 3단계 원래 수 확인 칸으로 구성됩니다. 3단계 선택지는 숫자를 한 번 더 누르는 방식이 아니라 `검산 결과 = 원래 수` 비교식으로 보여 줍니다. 각 단계가 끝나면 해당 칸이 채워지고, 다음 칸이 강조됩니다. 마지막 단계 뒤에는 바로 보상으로 넘어가지 않고 `검산 완료! n과 같아요.` 문구와 완성된 식을 보여 준 뒤, 학생이 `에너지 받기`를 눌러 보상을 엽니다.

왼쪽 보안실 영역은 플레이 중 금고 이름을 미리 공개하지 않습니다. 대신 금고 여는 힘에 따라 금고 주변 빛, 다이얼, 잠금등이 점점 켜집니다. 최종 결과 이름은 결과 화면에서만 표시됩니다.

### 보상 화면

한 문제의 3단계 계산이 끝나면 화면 중앙에 금고 여는 힘 이벤트가 뜹니다. 정답 문제는 금고 열림, 오류 경고, 강화 열쇠, 마스터키, 다시 잠김, 무지개 코어 중 하나가 나오며, 문제 안에서 한 번이라도 틀리면 오류 처리만 적용됩니다. 보이는 보상 문구는 `+n%`, `-n%`, `마스터키`, `무지개`처럼 한 덩어리 값으로 줄였고, 설명 문장은 접근성용 숨김 텍스트로 유지했습니다.

### 결과 화면

결과 화면은 도달 이름별 RasterStage 배경을 사용합니다. 자물쇠, 금고, 대형금고, 비밀금고, 보물고, 전설 금고 이미지가 따로 있습니다. 결과는 `data-result-visual-standard="generated-assets"`와 `data-result-render-mode="hybrid-generated-dynamic"`를 선언하고, SVG 오버레이가 도달 이름, 정답 수, 금고 여는 힘 미터, 다시하기 버튼 외형을 담당합니다. CSS 결과 카드(`result-stats`, `result-copy` 등)는 제거했습니다.

### 다시하기 결과 화면

금고 여는 힘이 부족하거나 정답 수가 부족하면 `result-retry-generated.webp`를 RasterStage 배경으로 사용합니다. 닫힌 금고와 다시 도전 문구를 보여 줍니다.

## 5. 매스몬 역할

이 차시에서 매스몬은 금고 보안실을 함께 살피는 동행 캐릭터로 등장합니다. 첫 화면 킹드래곤몬은 `cover-generated.webp` 안에 포함된 생성 장면이며, 커버 위 별도 HTML 이미지로 배치하지 않습니다. 학생이 얻는 중심 보상은 `금고 이름 도달`이며, 도감 수집 구조는 사용하지 않습니다.

## 7. 검증 기록

- `node --check`로 HTML 내부 스크립트 문법을 확인했습니다.
- VM 테스트로 문제 생성 항등식, 대표 오답 포함, 보상 이벤트 분기, 10문제 완주 흐름을 확인했습니다.
- Chrome headless로 첫 화면, 설명, 문제, 보상, 오류 보상, 성공 결과, 재도전 결과 화면을 캡처했습니다.
- 문제 생성 규칙은 나머지가 항상 1 이상이고 나누는 수보다 작도록 구성했습니다.
- 2단계와 3단계 선택지에는 나머지 더하기를 빠뜨린 오답이 포함됩니다.
- 프로덕션 HTML의 화면 건너뛰기 훅을 제거했습니다.
- 플레이 중 금고 이름은 강조하지 않고, 결과 화면에서만 도달 이름을 공개합니다.
- 결과는 금고 이름 하나로 끝나며, 별도 도감이나 누적 저장 구조를 만들지 않았습니다.
